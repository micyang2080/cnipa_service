## 1. 一页结论

**做成了什么**：cnipa-mcp 自动化国知局两个查询站——`cpquery.cponline.cnipa.gov.cn`（复审无效审查决定查询）与 `pss-system.cponline.cnipa.gov.cn`（专利审查信息查询／摘要附图）。三条业务流水线 + 登录链路均已在真实站点验证：

| 能力 | 状态 |
|------|------|
| 决定检索（12 项 filters 表单） | 真机验证通过 |
| 决定书详情（下钻 + 滚屏 OCR，固定 20 键） | 12/12 字段真机验证 |
| 摘要附图 PNG 落盘 | 端到端真机验证（39.7s/单次） |
| 账密自动登录（account.ini + 滑块 NCC 识别） | 2026-09-03 真机全链路通过 |
| MCP 工具层 + v2 契约 + 本地持久缓存 | 离线全绿；真机验收见 §8 |

**为什么慢（一句话版）**：目标站点部署瑞数反爬，**拒绝一切 CDP／自动化调试形态**——技术栈从 Playwright（有 DOM、有网络接口）推倒重来为「操作系统级键鼠 + 无障碍树 + 截图像素 + OCR」（什么接口都没有）；而站点真实行为**零文档**，只能由用户实跑、逐次留证、逐次勘误，其中多起是「先误诊、后由用户肉眼证据勘误」的方向级返工。

## 2. 背景与架构

### 2.1 转折：Playwright 被 CDP 检测出局

MCP 最初用 Playwright + 自带 Chromium 实现登录/检索/详情/附图。瑞数 antibot 升级后**拒绝一切 CDP／调试端口形态**，Playwright 全部能力（DOM、网络拦截、请求级下载）整条出局。`python/` 下 `*_pw.py` 系列保留作历史参考，实跑全部改走 `*_uia.py`。

### 2.2 现行架构：免 CDP 的 UIA 轨道

- **驱动**：pywinauto(UIA) 读无障碍树 + SendInput 真实键鼠，驱动**用户日常 Chrome**（无障碍树由 UIA 客户端接入时自动触发暴露——**无需任何特殊启动参数**，旧版 `--force-renderer-accessibility` 前提已于 2026-09-03 废除）。
- **代价**：没有 DOM、没有网络接口、没有下载 API——文本靠滚动截图 + Windows OCR，图片靠浏览器右键「另存为」／截屏裁剪，等待靠页态轮询。
- **平台边界（Windows-only）**：硬绑定在 UIA / SendInput（桌面自动化层，Windows API）；文本化现用 Windows OCR——本地另有能力更强的 AI OCR HTTP 服务可平替，属可换选型而非平台约束（暂不切换）。非 Windows 由 Node 层直接返回 `UNSUPPORTED_OS`（零 Python spawn）。Mac 取舍与估算见 [项目概要.md](项目概要.md)。
- **可复用结论**：任何被 CDP 检测拦住的站点迁移到 UIA，都可套用三级降级链：**DOM → 右键菜单 → 截屏**。

### 2.3 协作铁律（决定迭代节奏是「小时级」）

1. **Agent 永不直跑网站**（封号风险）——所有实跑由用户在本机执行；一轮「修改→验证」受限于人，而非机器。
2. **实跑失败不盲目重跑**——先从 `output/uia_runs/<run>/` 的探针（无障碍树、截图、OCR、窗口清单）做根因分析，修复后才约下一次实跑；首跑即探针、全程落盘。
3. 每次截图前 `set_focus`（等待期用户切窗，曾截到别的应用）。

## 3. 问题全景（六类归纳）

- **A 反爬对抗**：瑞数校验点击的「过程信号」（轨迹/悬停/按压时长），光标瞬移式程序点击被判非人 → `human_click` 拟人轨迹（14 步 ease-out + 抖动 + 悬停 + 按压）。
- **B 免 CDP 后「拿数据」要重新发明**：详情 URL 带会话加密 token 离站必空壳（只能点击进页）；决定书整页图片渲染零文本（只能滚屏截图 + OCR）；附图无下载 API（右键「另存为」为主路径）。
- **C UIA／无障碍树的陷阱**：Electron 与 Chrome 窗口类名完全相同（须进程映像双验）；Chrome 最小化坐标全 -31992；瞬变期树计数只能当观测值不能当控制流判据；附图从不以 Image 元素进树。
- **D 站点事实只能实证且第一诊断常错**：掉登录态 + 宽松结果区标记曾把页脚站标当附图交付（假成功 ok=true）→ 放行门只认强证据（`共N条`）+ 未登录 fail-fast；pss 表单是「占位长文案的智能框」而非标签配对输入框。
- **E 真实桌面是共享的**：用户控制台窗口遮挡致滚轮打进缓冲区；人机各开详情标签叠加；另存对话框模态拦路（此后失败分支必先 ESC）。
- **F 交付物质量与数据治理**：OCR 噪声冻结成自测夹具 + 合议组多候选择优；收割停机以「正文连续 2 屏不增长」为准；结尾判定用表格底边框像素检线（与文字内容无关）；payload（交付）与 debug（遥测）分离。

## 4. 代表性事件（全量见 UIA_RUNBOOK.md）

| 事件 | 根因 → 修复 |
|------|------------|
| Playwright 整栈出局 | 瑞数拒一切 CDP 形态 → 推倒为 UIA 轨道 |

| 键鼠打进宿主 Electron 应用 | 与 Chrome 窗口类名相同 → 进程映像双验 `chrome.exe` |

| 附图「假成功」交付页脚站标 | 隔夜掉登录态 + 宽松标记 → 强证据门 + 未登录 fail-fast |
| 附图定位三连勘误（不进树/稀疏图门槛失明/滚轮打进遮挡窗） | 图内容不可靠 → `locate_pane_frame` **认站点边框骨架、不认图内容**，换任何笔画风格无需重标定 |

| 05 附图端到端首胜 | 窗格定位→右键→另存→时间戳名→保存，39.7s（run `figure_20260902_151459`） |
| pss「申请号输入框未找到」 | 智能框形态：申请号只是 Tab、提交是 Text → 占位文案语义识别 |

## 5. 最终形态

### 5.1 MCP 工具面

| 工具 | 说明 |
|------|------|
| `cnipa_search_decisions` | 12 项 filters 检索复审/无效决定，items[] 固定 20 键 |
| `cnipa_fetch_decision_detail` | 决定书详情（推荐 search item 回环 `list_item` 入参，卡片精确值覆盖 OCR 噪声） |
| `cnipa_fetch_abstract_figure` | 摘要附图 PNG 落盘，返回 figure_path（用法 B 可独立调用） |
| `cnipa_login` | 账密自动登录：`{}`=读 account.ini 登录；`{username,password}`=存盘+登录；`{probe_only}`=只探测 |
| `cnipa_check_status` | 环境体检（零点击零站点交互） |
| `cnipa_save_credentials` | **已废弃**（改用 cnipa_login 传参即存），保留兼容 |

统一行为：返回一律是 `cnipa_contract.py` 白名单投影后的**契约 JSON**（内部遥测不出边界）；失败统一 `{success:false, error:<码>, message, hint}`；三业务工具**缓存优先**（`force_refresh` 强刷、响应带 `from_cache`/`cache_file`，见接口契约 §7）；遇 `NOT_LOGGED_IN` 自动登录重试一次。

### 5.2 代码与产物

| 文件 | 职责 |
|------|------|

附图三级取图链（任一步失败逐级回落）：**C 右键「图片另存为」拿原图（主路径）→ B 新标签整图截图 → A 窗格区域截屏裁剪**。附图定位「认边框不认图」：检测站点自绘附图窗格的边框骨架 + 「摘要」锚，与图画法无关，换图样不需重标定。

### 5.3 质量保障

- 离线验证阶梯（当前全绿）：`py_compile` → 各 runner `--selftest`（05 runner 40/40 含真实失败截图回放、04 runner 35 项）→ `offline_regression_v2.py`（真实卡片 + OCR 夹具 17 检）→ 缓存命中仿真 7/7 → `npm run build`（tsc 零错误）+ `scripts/mcp-contract-smoke.mjs`（schema 面 + FILTER_EMPTY 前置拦截）。
- 误识样本、失败页态文本、合成页面全部冻结为自测夹具——同一个坑不允许踩第二次。

## 6. 方法论沉淀（写给下一个被瑞数拦住的人）

1. **先问「手工怎么办」，再设计自动化**——右键另存为人手 10 秒，绕像素/裁剪是把简单问题做复杂。
2. 元素级证据优先于像素级猜测——但先证明该元素存在于这类页面。
3. 版式泛化找**与文字无关的物理/结构信号**（表格底边框、站点边框骨架）；词表/标点只配兜底。
4. 窗口/元素识别：类名标题是「门牌」，**内容才是身份**。
5. 弱特征只配遥测，**放行门要强特征**；未登录检测先于一切业务动作。
6. 控制流判据用稳定信号（页面文本标记）；瞬变期树计数只是观测值。
7. 滚动收割停机以**正文增长枯竭**为准；「字段齐了」只说明见过，不说明读完。
8. payload 是交付物、遥测是证据，分文件；溯源 = 来源标注 + 差异集。
9. 对行为风控站点，**点击的过程信号**与落点同等重要。
10. 外部进程边界的编码要有真机用例——离线夹具曾掩盖 PowerShell GBK 乱码整整一轮。
11. 免 CDP 迁移可复用降级链：**DOM → 右键菜单 → 截屏**。
12. 真实桌面是共享的：假设桌面上永远有别的窗口（遮挡/最小化/叠层/模态/同名类名）。

## 7. 为什么慢——诚实的账单

1. **节奏受限于安全协作模型**：Agent 永不直跑网站，约 30 轮实跑全靠用户执行，「发现现象→留证→根因→修复→再验证」周期以小时计。
2. **站点行为零文档**：会话加密 URL、整页图片渲染、自绘附图窗格、点击行为风控、智能输入框全部只能实测发现；图片渲染/懒加载还让程序自身传感器（树、截图）给出**否定假象**，多次形成「树里没有、截图里没有，用户肉眼明明有」的僵局。
3. **三次方向级返工**：PW→UIA（技术栈级）；04 直入 URL→点击进页+OCR（流程级）；05 附图定位 a11y→像素墨块→边框窗格（算法级）。每次返工前都有一轮「看似合理、实则错误」的方案先跑通了一部分——试错成本的大头。
4. **修复标准高**：每个修复冻结自测用例（误识样本/失败截图回放/合成页面），05 runner 自检从 11 项长到 40 项——慢的一部分代价花在「不让同一个坑踩第二次」。

## 8. 当前状态与遗留

**已验证**：三流水线 + 自动登录真机通过（证据 run：`figure_20260902_151459`、`detail_20260901_202133`）；v2 契约与本地缓存离线全绿（§5.3）。

**运维定位**：宿主机一次性准备 = 装 Python 依赖 + 配 `account.ini`；**Chrome 正常启动即可，无需任何特殊启动参数**。最终使用者只在 AI agent 里说自然语言（如「通过国知局查询申请号为 CN200410082265.7 的无效决定」），环境缺失时工具返回错误码 + hint 指导补环境，`cnipa_check_status` 可随时体检。

**遗留（按优先级）**：

1. 缓存真机验收（用户手动）：删 `output/cnipa_cache` 首跑写盘 → 二跑三工具 `from_cache=true` 无窗口日志；`force_refresh=true` 覆盖且 `from_cache=false`；回归样例 `200610004173.6` / `4W107577` 全链路。
2. 调用方（复审无效技能）按接口契约 §0 用法 A/B 各走一遍真实联调。
3. 05 附图图样泛化回归：密集线条图、多卡片结果页、无附图案件（负缓存）待逐类覆盖。
4. **macOS 轨道暂缓**：工具用户绝大多数在 Windows；Mac 估算与取舍见 [项目概要.md](项目概要.md)。
5. README/联调 RUNBOOK 对齐 UIA 视角。
