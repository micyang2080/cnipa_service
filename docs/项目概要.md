# cnipa-mcp 项目概要（一页速览）

> **日期**：2026-09-03。详细复盘见 [开发总结.md](开发总结.md)，逐条排障见 [python/UIA_RUNBOOK.md](../python/UIA_RUNBOOK.md)，接口字段见 [接口契约.md](接口契约.md)。

## 项目定位

跑在 **Windows 桌面**上的 MCP 服务，自动化查询国知局两个站点：**复审/无效审查决定**（cpquery）与**专利审查信息/摘要附图**（pss-system）。对外提供五个工具：决定检索、决定书详情、摘要附图下载、自动登录、环境体检。下游由「复审无效报告」技能消费：用检索列表、详情字段和附图 PNG 直接生成报告。

## 工期：原定约 2 天，实际 5 天


|             | 说明                                                                                                    |
| ----------- | ----------------------------------------------------------------------------------------------------- |
| **原定估算**    | 按常规 Web 自动化（Playwright / DOM / 网络接口）估算，约 2 天可交付                                                       |
| **实际路线**    | 国知局瑞数 antibot **拦截一切带调试端口的浏览器**，Playwright 整栈不可用，只能改为操作系统级键鼠 + 无障碍树 + 截图 OCR                          |
| **多出时间的去向** | ① 技术栈整体切换（Playwright → UIA）；② 详情、附图等流程多次方向调整；③ 站点行为无文档，只能真机试错；④ 为防封号，AI 不直接访问站点，约 30 轮验证均需本机人工操作，节奏偏慢 |
| **当前交付**    | 三条业务流水线与自动登录已真机通过；对外契约 v2；本地持久缓存；非 Windows 返回 `UNSUPPORTED_OS`                                        |


核心原因不是执行效率问题，而是**原定技术路线被反爬整栈否决**——工作从「调接口」变成了「模拟真人操作桌面」，复杂度与工期随之上升。

## 技术难点

1. **反爬封锁常规自动化**。凡带 CDP / 调试端口的浏览器（Playwright、Selenium 等）都会被识别拦截，「有 DOM、有网络接口」的方案在第一步即不可用，这也是复杂度和超期的主要来源。
2. **只能走操作系统级自动化**。用真实键鼠驱动日常 Chrome，经无障碍树读结构、滚动截图 + OCR 取正文、右键「图片另存为」取附图；没有公开 API，也没有下载接口。
3. **站点行为靠实测摸清**。例如详情链接带会话加密 token、决定书整页为图片、附图不进无障碍树、点击还校验轨迹与按压时长——均无文档，需真机留证、逐步修正。
4. **安全协作约束迭代节奏**。为降低封号风险，AI 不直接访问站点，实跑由用户在本机完成，一轮验证往往以小时计。

## 为何仅支持 Windows

1. 当前方案依赖 Windows 专属能力（pywinauto / UIA、SendInput），无障碍感知与键鼠注入无法直接平移到其他系统。
2. 非 Windows 环境会直接返回 `UNSUPPORTED_OS`，不启动 Python 或浏览器动作，行为明确、可预期。
3. OCR 可替换：正文目前用 Windows OCR；本地另有能力更强的 AI OCR 服务，需要时可以平替。平台限制来自桌面自动化层，而非 OCR。

## Mac 版暂缓的原因

- 使用本工具业务人员，机器都是用的 Windows，Mac 投入产出比偏低。
- 业务编排、拟人点击思路、风控经验和契约层可以复用，但桌面交互层（无障碍树、键鼠、窗口识别、截屏、另存对话框等）几乎要整层重写，不是换一个库就能完成。
- 粗估：在已有经验可复用的前提下，做到与 Windows 同级约需 **4～8 个工作日**；Chrome 无障碍完整度、风控表现、另存对话框差异等不确定因素，任一踩坑还可能再加 2～3 天。真机验证仍依赖本机人工，日历时间通常不短于开发估算。

## 当前状态

- 三条流水线与自动登录均已真机验证通过；对外契约为 v2（固定 20 键，调用方无需做键名映射）。
- 本地持久缓存已落地（无 TTL，决定类数据视为不变）：相同条件再次查询直接读本地文件，不再打开站点；需要时可用 `force_refresh=true` 强制重查。
- 后续事项：缓存真机验收、与调用方技能联调、附图图样泛化回归（详见开发总结 §8）。
