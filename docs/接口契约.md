# cnipa-mcp 对外接口契约（v2，2026-09-03）

> 面向调用方：**复审无效技能（patent-reexam-invalid-report）**——它拿本 MCP 的返回数据生成报告。
> 本文回答三件事：① 调用哪几个工具、传什么、返回什么字段；② 两种典型用法怎么串；③ 返回数据的"干净"边界（哪些字段绝不外泄）。
> **v2（2026-09-03）**：按 `docs/cnipa-mcp-技能侧契约要求.md` 定稿——检索 filters 扩到 **12 项**、items[]/detail 改为**固定 20 键**（键必须存在、缺值给 `""`）、`application_no` 统一**含点**、日期统一 `YYYY.MM.DD`、请求人统一 `petitioner`、每条带 `detail_url`、新增错误码 `FILTER_EMPTY / TOO_MANY_RESULTS / DETAIL_URL_MISSING`。v1 旧键名全部废弃（§1.3）。
> **v2 增补（2026-09-03）**：本地持久缓存落地（`docs/cnipa-mcp-本地缓存要求.md`）——三工具**缓存优先**，新增入参 `force_refresh`、成功响应附加 `from_cache`/`cache_file`，见 **§7**。

## 0. 一图流：两个工具调用方

```
用法 A（一站式）：本 MCP 独立完成
  cnipa_search_decisions(filters…) ──► items[]（固定 20 键，含 detail_url）
        │
        ├─► items[i] 整条 ──► cnipa_fetch_decision_detail({ list_item })   // 推荐回环
        │                          └─► detail（固定 20 键，决定日/请求日/法律依据/要点/合议组）
        └─► items[i].application_no ──► cnipa_fetch_abstract_figure(application_no) ──► figure_path
        ▼
  调用方拿「检索 items + 详情 detail + 附图文件路径」三样直接 ingest 生成报告（零键名映射）

用法 B（补图模式）：决定数据来自第三方（知产宝/iphouse 等），只要附图
  第三方结构化数据（含申请号）──► cnipa_fetch_abstract_figure(application_no) ──► figure_path
  ※ 无任何前置依赖：不需要先调本 MCP 的检索/登录，申请号直接进
```

## 1. cnipa_search_decisions —— 复审/无效决定检索

### 1.1 入参（v2：12 项 filters，对齐 cpquery「展开更多搜索项」）

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `library_type` | `'invalid' \| 'reexam'` | 否 | 无效决定库（默认）/ 复审决定库 |
| `filters` | object | **是** | **至少 1 个非空条件**，全空报 `FILTER_EMPTY`（Node 层即拦截，零 Python 调用） |
| `max_items` | int | 否 | 默认 50、上限 500；超过站点全量时 `truncated: true` |
| `page` | int | 否 | 起始页码从 1 起（默认 1），配合 max_items 自动翻页收集 |
| `force_refresh` | bool | 否 | 默认 `false` 缓存优先；`true`=跳过本地缓存强制重查国知局，成功后覆盖写缓存（§7.2） |

`filters` 12 键（多条件 = 站点 AND，与国知局 UI 一致）：

| 键 | 站点表单项 | 说明 |
|---|---|---|
| `application_no` | 申请号/专利号 | 如 `200610004173.6`；含/不含点、CN/ZL 前缀均接受，自动规范化 |
| `invention_title` | 发明名称 | 支持模糊 |
| `patent_type` | 专利类型（下拉） | 枚举 `invention \| utility_model \|\ design`，内部映射站点中文 |
| `ipc_class` | 分类号 | 如 `A61K31/137` |
| `decision_no` | 决定号 | 如 `38430` |
| `case_no` | 案件编号 | 如 `4W107577` |
| `patentee` | 专利权人 | |
| `petitioner` | 请求人 | 无效库=无效宣告请求人；复审库=复审请求人（按库自动选表单框） |
| `panel_leader` | 合议组组长 | |
| `panel_examiner` | 主审员 | |
| `panel_member` | 参审员 | |
| `agency` | 代理机构名称 | |

## 3. cnipa_fetch_abstract_figure —— 摘要附图（用法 A/B 公用）

### 入参（建议契约，与现 MCP schema 一致）

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `application_no` | string | 是 | 申请号，13 位含点如 `200610004173.6`；CN/ZL 前缀、带/不带校验位点号均可（内部规范化） |
| `save_path` | string | 否 | 落盘绝对路径（扩展名生效，缺省按 `.png`）；**不传时**产物落在本次 run 目录 `output/uia_runs/figure_<时间戳>/figure_saveas_*.png` 并以绝对路径返回。建议技能侧传入以便归档 |
| `force_refresh` | bool | 否 | 默认 `false` 缓存优先（png/负缓存命中不开 pss）；`true`=清 `.no_figure` 标记后强制重抓，成功后覆盖写 png（§7.2/§7.4） |

**无任何前置依赖**：不要求先调检索、不要求本 MCP 会话/登录态（依赖的是操作者桌面 Chrome 已登录 CNIPA，见 §5 运行前提）。用法 B 直接调它即可。

### 返回（干净结构）

成功：

```jsonc
{
  "success": true,
  "application_no": "200610004173.6",
  "figure_path": "C:\\git\\Mcps\\cnipa-mcp\\python\\output\\figures\\CN200610004173.6.png",
  "method": "saveas"                  // 附图落地方式：saveas=另存为原图（主路径）| orig_tab=新标签整图 | crop=截图裁剪保底
}
```

失败（**注意：失败结构不含 application_no**，只固定 4 键）：

```jsonc
{
  "success": false,
  "error": "NO_FIGURE",              // 机器可判错误码（见 §4）
  "message": "详情页未检测到摘要附图区域",
  "hint": "该案件可能无附图（如纯方法专利），请调用方按缺图处理"
}
```

### 3.1 技能对接速查（用法 B · 知产宝场景，2026-09-03 与技能源码对拍）

```
对每个 case（application_no 来自知产宝结构化数据）：
  ① 调 cnipa_fetch_abstract_figure({ application_no })     // 未登录时自动登录重试
  ② 成功 → 收集 { application_no: figure_path }             // application_no 原样回显，做键即精确匹配
  ③ 失败 error=NO_FIGURE → 按"无附图"处理（技能 fetch 脚本 --skip-if-missing 默认容错）
  ④ 全部调完把 map 写成 JSON 文件，传给技能：
     python fetch_abstract_figures.py --work-dir … --run-id … --figure-map <该文件>
     （技能侧对 `app_no` 与 `CN{app_no}` 两种键都兼容；figure_path 必须是已存在的文件，脚本会 is_file 校验）
```

`figure_path` 为绝对路径、文件真实存在（技能侧有 `Path(fig).is_file()` 校验）；直接把 MCP 返回值塞进 figure-map 即可。

## 4. 「干净」边界（对外输出白名单制度）

原则：**MCP 边界只投影契约字段；过程证据留在本地 run 目录，永不外出。**

- 实跑 payload 里的内部遥测字段——`mode / run_dir / input_file / started_at / finished_at / steps / img_candidates / total_before / window_title / logged_in / screenshot / tree_flat / ocr_pages / cleanup_ok / elapsed_s / app_no_match / case_no_match`——**一律不出 MCP 边界**，它们是排障用的，收件方（复审无效技能）不需要、也不应感知。
- 字段投影在**Python 侧完成**（runner 产出契约 JSON），Node 层原样透传——这样 MCP 层不需要逐字段过滤逻辑，杜绝"漏网字段"。
- 证据文件（截图/树 dump/debug.json）仍按 `clean_output.py` 的目录策略留在 `output/uia_runs/`，属于运维面，不属于接口面。
- 错误码固定集合（终版，由 `cnipa_contract.classify_error` 归类，另含 Node 前置码）：`UNSUPPORTED_OS`（非 Windows——**Node 层 `process.platform !== 'win32'` 即拦截，零 Python spawn**）、`WINDOW_NOT_FOUND`（没找到目标 Chrome）、`A11Y_DISABLED`（无障碍树未暴露，罕见兜底）、`NEED_CREDENTIALS`（account.ini 未配置账密，hint=在对话中提供账号密码）、`CAPTCHA_FAIL`（登录滑块未通过）、`AUTH_REJECTED`（账密被国知局拒绝）、`NOT_LOGGED_IN`（Chrome 无登录态，hint=自动登录或人工登录后重试）、`NO_RESULT`（检索无命中）、`NO_FIGURE`（无摘要附图）、`PARSE_FAIL`（页面结构变了）、`TIMEOUT`、`INVALID_INPUT`、`RUNTIME_FAIL`（兜底）。每个都带 `message`（给人看）与 `hint`（调用方可执行的下一步）。
- **v2 新增三码**（2026-09-03，§技能侧契约 6）：`FILTER_EMPTY`（filters 12 键全空——**Node 层 schema 校验后前置拦截**，零 Python spawn；runner 侧同规则双保险）；`TOO_MANY_RESULTS`（命中超 max_items 上限 500——正常截断以 `truncated: true` **字段**表达非致命，此码留给 runner 明确上报"结果过多"的场景，hint=收紧条件）；`DETAIL_URL_MISSING`（命中记录缺申请号/案件编号无法构造链接——常态直接给 `detail_url: ""`，此码为 classify_error 预留归类）。
- **密码零出界**：登录链路（`cnipa_login`/account.ini）的密码只存在于 account.ini 与内存；payload.json / 契约 JSON / stdout 一律不含（`cnipa_contract.clean_login` 白名单无 password 键，selftest 有泄漏回归断言）。account.ini 已入 `.gitignore`。

## 5. 运行前提与自动登录（两条用法共用，须写进调用方文档）

0. **操作系统必须是 Windows**（pywinauto/UIA + 桌面键鼠）。macOS／Linux 上任意工具立刻返回 `UNSUPPORTED_OS`（Node 层拦截，见 README「平台要求」）；Mac 自动化轨道未做。
1. 操作者桌面 Chrome **正常启动即可，无需任何特殊启动参数**（无障碍树由 UIA 客户端接入自动触发暴露；旧版要求的 `--force-renderer-accessibility` 前提已于 2026-09-03 废除）。**登录不再是前提**——2026-09-02 起 UIA 轨道恢复了第一天 PW 时代的账密自动登录（填表 + verify 滑块 CV 识别 + 拟人拖动 + 门户落地兜底），凭证来自 `account.ini`。
2. 实跑在用户桌面执行（防封号铁律：Agent 不直接碰线上）；MCP 工具调用 → UIA runner 在宿主机驱动该 Chrome。

### 5.1 凭证流程（account.ini，`python/cnipa_creds.py`）

位置：`CNIPA_ACCOUNT_INI` 环境变量 > `python/account.ini`。格式：`[cnipa] username / password / login_type(natural|legal)`。

**最终用户体验（目标态，已实现）**：

1. 用户新建对话直接说：「通过国知局查询申请号为 CN200410082265.7 的无效决定」（也可同句带账密：「…，账号：zhangsan，密码：1234」）。
2. Agent 调 `cnipa_search_decisions` 等工具；宿主 Chrome 无登录态时 runner 报 `NOT_LOGGED_IN`，Node 层 `withAutoLogin` 自动触发登录 runner。
3. account.ini 没有凭证 → 返回 `NEED_CREDENTIALS`（含 hint）→ **Agent 在对话中向用户索要账号密码**（用户下一句给出即可）。
4. Agent 调 `cnipa_login`（带 `username/password`）→ 自动保存 account.ini（今后免输）→ 自动完成 SSO 登录 → 原查询自动重试。
5. 之后所有对话：凭证文件已有 → 全自动，无需任何人工干预。

`cnipa_login` 也可独立调用：`{}`=读文件登录；`{username,password}`=存盘+登录；`{probe_only:true}`=只探测（窗口/登录态/凭证，零动作）。

### 5.2 登录 runner 细节（`python/run_cnipa_login_uia.py`）

- **大脑复用第一天 PW 成果**：拖动轨迹参数照搬 `human_drag`（30 步 ease-out + 停止期）；入口 URL 用 CAS `sso.cponline/login?service=<cpquery>`（避开 tysf 落门户坑）+ 门户落地兜底跳回。滑块缺口识别为**内置 `_ncc_gap_detect`**（Sobel 梯度 NCC 集成 + 微拖标定 piece_w/scale，2026-09-03 重写；不再 import PW 版 `src/utils/gap_detection.py`，ddddocr 依赖已移除），6 例离线回归误差 ≤2px。
- **只换手脚**：DOM 选择器 → a11y 树检索（`classify_login_fields`：placeholder 命名 + 几何兜底）；`page.screenshot` → 窗口截图裁剪（截图/逻辑 px 统一 ratio 换算，DPI 一并吃掉）；`page.mouse` → SendInput 拟人原语（`cnipa_uia.human_drag / drag_hold_start / drag_held_to / drag_release`）。
- 滑块几何首次实跑校准：runner 每步落盘截图/候选树；失败报 `CAPTCHA_FAIL` 并提示 `--captcha-replay <run目录>` 离线校准（不重复登录即可迭代识别参数）。
- 账密被拒（页面出现"密码错误"等）→ `AUTH_REJECTED`，hint 提示用 `cnipa_login` 更新凭证。

## 6. 接线实施结果（已完成）

**当前代码现状**：MCP 层已接线到 UIA runner（本节原为"提案"，现已实施并通过验证）。§1–§4 就是**实际暴露**的契约。

**实施方式（与原提案的差异用 ≡ 标注）**：

1. Python 侧：新增 `python/cnipa_contract.py`（白名单投影 + 错误分类 + 发射开关）；UIA runner 的终态钩子 `_finish` 末尾各接一行 `cnipa_contract.maybe_emit(tool, payload)`。≡ 开关从 `--emit-json` 参数改为环境变量 `CNIPA_EMIT_JSON=1`——本地手工实跑不受任何影响。
2. 发射协议：runner 照常落盘 run 目录，另把契约 JSON 打到 stdout（一个以 `{` 开头的独立行）。≡ 注意 JSON **不保证是字面"末行"**（其后可能还有 `[uia] 完成…` 日志）→ Node 层解析规则是"**自尾向首找最后一个可解析 JSON 行**"。
3. Node 侧：`src/runPython.ts` 重写为 `runCnipaUiaScript`——入参写 `output/uia_inputs/<脚本>_<时间戳>.json` 再以 argv[1] 传给 runner；**exit≠0 时先解析契约 JSON**（UIA runner 业务失败 exit 1 但仍发射），解析不到才按超时/运行时错误上报。

## 7. 本地持久缓存（2026-09-03 增补，已实施）

复审/无效决定是已发布的历史文书，内容稳定 → **无 TTL**（区别于可变数据）。检索/详情/附图三类结果持久化本地，各工具**先查缓存、未命中再访国知局**；命中时返回与线上完全一致的契约 JSON，且**不打开任何浏览器/站点窗口**。实现落点：`python/cnipa_cache.py`（路径/键/读写原语）+ `cnipa_contract.write_search_cache / write_detail_cache`（契约投影落盘）+ 三 runner 入口短路（命中在任何窗口操作前返回）。

### 7.1 目录与环境变量

```
{CNIPA_CACHE_ROOT}（默认 = {repo}/output/cnipa_cache）
├── search/{invalid|reexam}/{query_key}.json            # 检索契约 JSON
├── detail/{invalid|reexam}/{application_no}__{case_no}.json
└── figures/{application_no}.png                        # 摘要附图（13 位含点文件名）
    figures/{application_no}.no_figure                  # 负缓存标记（确认无附图）
```

| 环境变量 | 含义 |
|---|---|
| `CNIPA_CACHE_ROOT` | 缓存根目录（默认 `{repo}/output/cnipa_cache`） |
| `CNIPA_CACHE_DISABLED=1` | 全局跳过读/写（联调用）；`force_refresh=true` 只跳过读、成功后仍覆盖写 |

缓存文件内容 = `cnipa_contract.clean_*` 投影后的**契约 JSON 本身**（不含 `from_cache`/`cache_file`——这两个键只出现在响应里），故可直接 `ingest_cnipa_decision_result.py --input {cache_file}`。

### 7.2 入参 `force_refresh`（三工具统一）

| 参数 | 类型 | 默认 | 说明 |
|---|---|---|---|
| `force_refresh` | bool | `false` | `true`=跳过读缓存强制重查国知局，成功后**覆盖**写缓存；figure 工具同时先清 `.no_figure` 标记（有图重抓后不被旧标记挡住） |

### 7.3 出参 `from_cache` / `cache_file`（成功响应附加，技能可忽略）

| 字段 | 类型 | 说明 |
|---|---|---|
| `from_cache` | bool | `true`=本次未访问国知局（缓存命中，`method:"cache"`）；`false`=线上抓取且已写缓存 |
| `cache_file` | string | search/detail=持久契约 JSON 绝对路径（可 `ingest --input`）；figure=附图 PNG 绝对路径 |

- **每次 search/detail 成功（无论命中与否）都带 `cache_file`**，指向 §7.1 持久路径，不指向含遥测的 `uia_runs/run_*/payload.json`。
- **错误响应不带这两个键**（失败结构固定 4 键，见 §3 失败例）；附图负缓存命中时报 `NO_FIGURE`，`message` 注明「本地负缓存命中，未访问 pss」，`hint` 提示 force_refresh 重试。

### 7.4 各工具缓存规则

- **检索**：`query_key = sha256(json({library_type, filters 规范化, max_items}, sort_keys=True))[:16]`——`max_items` 入键（不同上限=不同缓存）；同键缓存 `truncated:true` 且本次 `max_items` 更大 → 视为未命中重查覆盖；`filters` 全空不读不写（FILTER_EMPTY）。**仅 page=1 语义读写缓存**（page>1 起跑会丢弃起始页之前的卡片，语义不同，天然走线上）。
- **详情**：键 = 规范化 `application_no`__`case_no`（CN/ZL 前缀、含/不含点自动归一）；**双号齐全才写**（缺任一号走线上不落盘）；`library_type` 可由 `list_item.review_type` 推断。
- **附图**：png 命中（size>0）→ 直接返回（给了 `save_path` 则拷贝/按扩展名 PIL 转码过去，`method:"cache"`）；`.no_figure` 命中 → 直接 `NO_FIGURE` 不开 pss。负缓存**只在详情页确认无附图区域那一点**写入——登录过期/超时/0 命中等失败不写标记、不挡重试；人工删标记文件即可强制重试。
- 缓存命中路径在任何 UIA 窗口操作（`require_window`/`find_any_chrome`）之前 return——离线即可仿真验证，无封号风险。
